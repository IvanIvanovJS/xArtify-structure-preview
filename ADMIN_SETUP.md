# Admin Panel Setup Guide

## Първоначално създаване на Admin акаунт

### 1. Настройка на Environment Variables

Добавете следната променлива в `.env.local`:

```bash
ADMIN_CREATION_KEY=your_secure_admin_key_here_min_10_chars
```

**Важно:** Използвайте силен, уникален ключ с поне 10 символа.

### 2. Създаване на първия Admin акаунт

1. Отидете на `/setup-admin`
2. Попълнете формата с:
   - Пълно име
   - Email адрес
   - Парола (минимум 8 символа)
   - Потвърждение на паролата
   - Admin ключ (от environment variable)

3. Натиснете "Създай Admin Акаунт"

**Забележка:** Този процес може да се извърши само веднъж. След създаването на първия admin акаунт, страницата `/setup-admin` ще пренасочва към `/admin`.

### 3. Вход в Admin Panel

1. Отидете на `/login`
2. Влезте с новосъздадения admin акаунт
3. Ще видите щит икона (🛡️) в header-а
4. Кликнете върху нея или отидете директно на `/admin`

## Admin Panel Функционалности

### Dashboard (`/admin`)
- Общ преглед на платформата
- Статистики за потребители, картини, курсове
- Последна активност
- Графики и метрики

### User Management (`/admin/users`)
- Списък с всички потребители
- Търсене и филтриране
- Промяна на роли (USER → ARTIST → ADMIN)
- Детайлна информация за всеки потребител

### Промяна на роли

1. Отидете на `/admin/users`
2. Намерете потребителя (чрез търсене или филтър)
3. Кликнете "Промени роля"
4. Изберете новата роля
5. Въведете причина за промяната
6. Потвърдете промяната

**Валидни роли:**
- `USER` - Обикновен потребител
- `ARTIST` - Художник (може да качва картини)
- `ADMIN` - Администратор (пълен достъп)

## Security Мерки

### 1. Автентификация
- Всички admin routes изискват валидна сесия
- Проверка за ADMIN роля на сървърната страна
- Автоматично пренасочване при липса на права

### 2. Rate Limiting
- API endpoints имат rate limiting
- Максимум 10 промени на час за един admin
- 30 заявки на минута за статистики

### 3. Валидация
- Всички входни данни се валидират с Zod
- Проверка за уникалност на email
- Минимални изисквания за пароли

### 4. Аудит
- Всички промени се логват в конзолата
- Записва се кой, кога и защо е направил промяната
- IP адрес и timestamp за всяка операция

### 5. Защита срещу само-промяна
- Admin не може да променя собствената си роля
- Защита срещу случайно понижаване на права

## API Endpoints

### `POST /api/admin/promote-user`
Промяна на роля на потребител

**Body:**
```json
{
  "userId": "user_id_here",
  "newRole": "ARTIST",
  "reason": "Причина за промяната"
}
```

### `GET /api/admin/promote-user`
Получаване на списък с потребители

**Query Parameters:**
- `page` - Номер на страница (по подразбиране: 1)
- `limit` - Брой потребители на страница (по подразбиране: 20, максимум: 100)
- `search` - Търсене по име или email
- `role` - Филтър по роля (USER, ARTIST, ADMIN)

### `GET /api/admin/stats`
Получаване на статистики за dashboard

### `POST /api/admin/create-admin`
Създаване на първия admin акаунт

**Body:**
```json
{
  "email": "admin@example.com",
  "password": "secure_password",
  "name": "Admin Name",
  "adminKey": "admin_creation_key"
}
```

## Troubleshooting

### Проблем: "Нямате права за тази операция"
**Решение:** Уверете се, че сте логнати с admin акаунт и ролята е ADMIN.

### Проблем: "Admin ключът не е конфигуриран"
**Решение:** Добавете `ADMIN_CREATION_KEY` в `.env.local` файла.

### Проблем: "Вече съществуват admin потребители"
**Решение:** Използвайте `/admin/users` за промоутване на съществуващи потребители.

### Проблем: "Не можете да променяте собствената си роля"
**Решение:** Това е защитна мярка. Използвайте друг admin акаунт за промяна.

## Best Practices

1. **Регулярни Backups:** Правете редовни backups на базата данни
2. **Сигурни пароли:** Използвайте силни пароли за admin акаунтите
3. **Мониторинг:** Следете логовете за подозрителна активност
4. **Ограничен достъп:** Давайте admin права само на доверени лица
5. **Документиране:** Записвайте причините за промените в ролите

## Поддръжка

При проблеми или въпроси:
1. Проверете логовете в конзолата
2. Уверете се, че всички environment variables са настроени
3. Проверете дали базата данни е достъпна
4. Тествайте с различни браузъри и устройства
